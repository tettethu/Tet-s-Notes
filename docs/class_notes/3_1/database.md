## Chap 3. 关系数据库语言 SQL

- 基本术语
	- SQL: 介于关系代数与关系演算之间的语言; 四大功能 = 查询(DQL) + 操纵(DML) + 定义(DDL) + 控制(DCL); 核心只用 9 个动词
	- 基本表: 独立存在的表, 一个关系对应一个基本表
	- 视图(View): 从一个或多个基本表/视图导出的虚表, 只存定义不存数据
	- 存储文件: 物理结构, 对用户透明
	- 三级模式对应: 基本表 -> 模式, 视图 -> 外模式, 存储文件 -> 内模式
- 3.1 SQL 概述
	- 特点(常考)
		- 综合统一: DDL/DML/DCL 集于一体
		- 高度非过程化: 只说"做什么"不说"怎么做"(存取路径由系统定)
		- 面向集合的操作: 操作对象和结果都是元组集合
		- 两种使用方式同一语法: 独立(交互式) + 嵌入式
		- 语言简洁: 9 个核心动词
- 3.2 数据定义 (DDL)
	- 建表: `CREATE TABLE <表名>(<列名> <类型> [列约束]..., [表级约束])`
		- 列级约束: `NOT NULL` / `UNIQUE` / `DEFAULT` / `CHECK`
		- 表级约束: `PRIMARY KEY` / `FOREIGN KEY..REFERENCES..ON DELETE {RESTRICT|CASCADE|SET NULL}` / `CHECK`
	- 改表: `ALTER TABLE` + `ADD`(加列/约束) / `DROP`(删列/约束) / `MODIFY`(改列定义)
	- 删表: `DROP TABLE`(表/数据/索引一起删, 慎用)
	- 索引: `CREATE [UNIQUE][CLUSTER] INDEX..ON 表(列[ASC|DESC])`; `DROP INDEX`
		- B+树索引(动态平衡) / HASH索引(查得快); 属于内模式; 主键和 UNIQUE 列 DBMS 自动建索引
	- 模式: `CREATE SCHEMA <名> AUTHORIZATION <所有者>`; `DROP SCHEMA..[RESTRICT|CASCADE]`; 模式 = 命名空间
- 3.3 数据查询 (DQL, 核心)
	- 基本结构: `SELECT [ALL|DISTINCT] 列 FROM 表 [WHERE 行条件] [GROUP BY 列 [HAVING 组条件]] [ORDER BY 列 [ASC|DESC]]`
	- 单表查询
		- 目标列: 指定列 / `*` 全部 / 算术表达式 / 列别名
		- `DISTINCT` 去重(缺省是 `ALL`)
		- WHERE 谓词: 比较(`= > < >= <= != <>`) / `BETWEEN..AND` / `IN` / `LIKE`(`%` 任意串, `_` 单字符, `ESCAPE` 换码) / `IS [NOT] NULL`(不能用 =) / `AND OR NOT`(AND 优先级高于 OR)
	- `ORDER BY`: 排序; 空值在 ASC 时最先显示, DESC 时最后显示
	- 聚集函数: `COUNT/SUM/AVG/MAX/MIN`([DISTINCT|ALL]); 只能在 SELECT 和 HAVING 中用, 不能用在 WHERE
	- `GROUP BY`: 按列分组, 聚集函数分别作用于每组; `HAVING` 筛选组
		- WHERE vs HAVING: WHERE 作用于行(基表/视图), HAVING 作用于组
	- 连接查询(多表)
		- 等值连接(`=`) / 非等值连接 / 自然连接(去掉重复列)
		- 自连接: 表与自身连接, 必须起别名区分
		- 外连接: `LEFT/RIGHT OUTER JOIN..ON..`; 以主体表为主, 不满足条件的元组也输出(补 NULL)
		- 复合条件连接: WHERE 中多个连接条件
	- 顺序:
		```text
		from
		where
		group by: group by key1, key2 -> 只能 select key1, key2, 对 user 其实是得到一个属性为 key1,key2,...keyn, group_rows 的复合n+1属性表, 一行一个group, 一个group, 之后 having 只能访问 key/group_rows, 是筛group而不能在group里筛行; select 只能属性1中的某个key, 或者对 group_rows 做聚集 e.g. avg(sc.grade)
		having
		select
		order by
		```
	- 嵌套查询(子查询)
		- `IN` 子查询
		- 带比较运算符的子查询(子查询确定返回单值时)
		- `SOME/ANY`(任意一个) vs `ALL`(所有); 等价转换: `>ALL = >MAX`, `<ALL = <MIN`, `>SOME = >MIN`, `<SOME = <MAX`, `=SOME = IN`, `<>ALL = NOT IN`
		- `EXISTS/NOT EXISTS`: 只返回真/假; 子查询非空则 EXISTS 为真; 目标列常用 `*`
		- 相关子查询: 内层引用外层的值, 需对外层逐元组反复执行
	- 集合查询: `UNION`(去重) / `UNION ALL`(保留重复) / `INTERSECT`(交) / `EXCEPT`(差); 各查询列数与对应类型须一致
- 3.4 数据操纵 (DML)
	- 插入: `INSERT INTO 表[(列)] VALUES(值)`; 也可多记录 / 子查询结果插入(`INSERT INTO 表 <子查询>`)
	- 删除: `DELETE FROM 表 [WHERE 条件]`(删的是元组, 不是表本身)
	- 修改: `UPDATE 表 SET 列=值[,..] [WHERE 条件]`
- 3.5 视图
	- 定义: `CREATE VIEW 视图名[(列)] AS <子查询> [WITH CHECK OPTION]`
		- 子查询用了函数/表达式时必须显式给列名; `WITH CHECK OPTION` 保证增删改后仍满足视图条件
	- 虚表: 不存数据只存定义; 查询时把视图条件与查询条件合并, 再转成对基表的查询
	- 删除: `DROP VIEW`; 基表删了视图还在但已无法引用
	- **更新限制**(考点): 更新最终落到基表, 但
		- 行列子集视图可更新(例外: 基表中视图未含的列既无默认值又非空, 则不能 INSERT)
		- 用了 `DISTINCT` / `GROUP BY` / 聚集函数的视图不可更新
		- 多表连接或含嵌套查询的视图通常不可更新
	- 优点: 逻辑数据独立性 + 简化用户操作 + 数据安全保护; 对应三级模式中的外模式
- 3.6 数据控制 (DCL)
	- 权限: 用户级 vs 表级(SQL 标准支持表级); 表级权限有 SELECT/INSERT/UPDATE/DELETE/REFERENCES
	- 授权: `GRANT <权限> ON TABLE 表 TO <用户> [WITH GRANT OPTION]`; `ALL PRIVILEGES` = 全部权限; `WITH GRANT OPTION` 表示可转授
	- 收回: `REVOKE <权限> ON TABLE 表 FROM <用户>`
	- 角色(ROLE): 一类共同特征用户的总称, 便于管理; `CREATE ROLE`
- 3.7 嵌入式 SQL
	- 嵌入式 SQL(ESQL): 把 SQL 嵌入高级语言(称宿主语言/主语言, 如 C/Java/Python), 用过程性弥补 SQL 复杂应用的不足
		- 前缀 `EXEC SQL`; 结束标志随主语言不同(C 中用 `;`, COBOL 中用 `END-EXEC`)
		- 分可执行语句 + 说明性语句
	- 主变量(共享变量): 主语言与 SQL 传值的桥梁, SQL 中用 `:变量` 引用
	- 单记录查询: 用 `INTO` 子句把结果存入主变量
	- 游标(Cursor): 解决"SQL 返回多元组, 主语言一次只处理一行"的矛盾; 四步 = 定义 `DECLARE` -> 打开 `OPEN` -> 使用 `FETCH..INTO` -> 关闭 `CLOSE`
	- 静态 vs 动态 SQL: 静态(预编译时语句结构已定, 只有主变量值运行时输入); 动态(运行时临时组装语句, 用 `PREPARE`+`EXECUTE` 或 `EXECUTE IMMEDIATE`)
	- 调用层接口(了解): JDBC(Java 标准接口, java.sql + 驱动程序) / ODBC(微软, 任意语言, 统一接口); openGauss 客户端有 gsql / Data Studio

## Chap 4. 数据依赖与关系模式规范化

- 基本术语
	- 关系的形式化定义: $$R(U, D, DOM, I, F)$$
	- 数据依赖(Data Dependency): 一个关系中各属性值相等与否体现的属性间制约关系, 是数据语义的体现; 是上位概念, 最重要的两种是 FD 和 MVD
		- 函数依赖(FD): $X \rightarrow Y$, X 值定了 Y 值就定了
		- 多值依赖(MVD): $X \twoheadrightarrow Y$, 一个 X 值对应一组 Y 值, 且与其余属性无关
	- 决定子(Determinant): FD $X \rightarrow Y$ 中的左部 X
	- 内涵 vs 外延: 内涵=关系模式(稳定), 外延=关系实例 r(随时间变)
	- 范式(Normal Form, NF): 衡量关系模式规范化程度的标准
- 4.1 问题的提出
	- 坏模式(如 SCT 合在一张表)的四大问题: 数据冗余, 更新异常, 插入异常, 删除异常
	- 根因是模式中存在不合适的数据依赖; 解决办法是分解关系模式
- **4.2 数据依赖**
	- 函数依赖的定义(定义4.1)
		- 对 r 任意两元组, $t_1[X]=t_2[X]$ 必有 $t_1[Y]=t_2[Y]$, 则 $X \rightarrow Y$
		- FD 是语义概念: 须对 R 的**所有**实例成立, 只能由语义确定
		- 区分: "满足依赖的关系"(某实例上成立) vs "模式上成立的依赖"(所有实例成立)
	- 完全/部分函数依赖(定义4.2)
		- 完全依赖 $X \xrightarrow{F} Y$: $X \rightarrow Y$ 成立且去掉 X 任一属性就不成立(左部无冗余)
		- 部分依赖 $X \xrightarrow{P} Y$: 否则
	- 平凡/非平凡函数依赖(定义4.3)
		- 平凡: $Y \subseteq X$, 必然成立, 不讨论
		- 非平凡: $X \rightarrow Y$ 且 $Y \not\subseteq X$
	- 传递函数依赖(定义4.4): $X \rightarrow Y$, $Y \rightarrow Z$ 且 $Y \nrightarrow X$, 则 Z 传递依赖于 X ($Y \nrightarrow X$ 是关键, 否则退化为直接依赖)
	- Armstrong 公理
		- A1 自反律: $Y \subseteq X \Rightarrow X \rightarrow Y$
		- A2 增广律: $X \rightarrow Y \Rightarrow XZ \rightarrow YZ$
		- A3 传递律: $X \rightarrow Y,\ Y \rightarrow Z \Rightarrow X \rightarrow Z$
		- 导出规则: 合并($X \rightarrow Y, X \rightarrow Z \Rightarrow X \rightarrow YZ$), 伪传递($X \rightarrow Y, WY \rightarrow Z \Rightarrow WX \rightarrow Z$), 分解($X \rightarrow Y, Z \subseteq Y \Rightarrow X \rightarrow Z$)
	- 逻辑蕴含(定义4.5) vs 逻辑导出(定义4.7): 前者语义角度($F \models X \rightarrow Y$), 后者推导角度($F \vdash X \rightarrow Y$)
	- 函数依赖集闭包 $F^+$(定义4.6): F 逻辑蕴含的全部 FD 的集合; 计算 $F^+$ 是 NP 完全问题
	- 属性集闭包 $X^+$(定义4.8)
		- $X_F^+ = \{A \mid F \vdash X \rightarrow A\}$; 算 $X^+$ 远比算 $F^+$ 省
		- 引理4.2: $X \rightarrow Y$ 可导出 $\iff Y \subseteq X^+$
		- **算法4.1**(求 $X^+$): 反复找左部 $\subseteq$ 当前集的 FD, 把右部并入, 直到不变或 $=U$
	- 正确性与完备性
		- 正确性(soundness): 导出的必被蕴含
		- 完备性(completeness, 定理4.1): 蕴含的必可导出
		- 二者保证"逻辑导出"="逻辑蕴含"
	- 等价覆盖(定义4.8'): $F^+ = G^+$ 则等价; 引理4.3: 等价 $\iff F \subseteq G^+$ 且 $G \subseteq F^+$
	- 最小函数依赖集 / 最小覆盖(定义4.9)
		- 三条件: (1)右部全为单属性 (2)左部无多余属性 (3)无多余的整条 FD
		- 定理4.2: 每个 F 都等价于某个最小覆盖
		- 求法: 
			1. 右部拆单属性
			2. 去左部多余属性
			3. 去多余 FD: 尝试去掉每一个FD, 看看能不能从其他FD推出. 如果能推出/这个FD的右部仍然属于左部关于这个依赖集的闭包
		- 最小覆盖不唯一, 与处理顺序有关
	- 多值依赖(MVD): 理解为在 X 固定(固定是指单属性取固定值/属性集取固定组合)的时候, 属性集合 Y 和剩余属性集合(Z=U-X-Y) 独立, 而独立是指按固定 x 筛选出来的元组里, 每个 y 取值搭配过的 z 组合集合是相同的. 也就是如果 y1 和 z1 在一行过, 那么 y2 肯定也和 z1 在一行过 e.g. 数学课, 如果老师A用过教材1, 那么老师B也一定用过教材1, 不然就不满足MVD
		- 引例 Teaching(教员T, 课程C, 参考书B): 一门课多教员共用一套参考书
		- 形式定义(定义4.11): 令 $Z = U - X - Y$, 交换两元组在 Y 上的值得到的元组仍在 r 中, 则 $X \twoheadrightarrow Y$
		- 产生条件: 关系 ≥3 属性, 其中两个多值且只依赖第三个
		- 危害与消除: 非平凡非FD的MVD致冗余, 用投影分解成两个关系, 每个只存一个多值属性
		- 推导规则: 
			- A4 互补律($X \twoheadrightarrow Y \Rightarrow X \twoheadrightarrow U - X - Y$): 独立是相对的, Y 和 U-X-Y 互相独立
			- A5 扩展律: $X \twoheadrightarrow Y$ 且 $V \subseteq W \Rightarrow WX \twoheadrightarrow VY$ (两边各加属性, 加的 V 必须被 W 包住)
			- A6 传递律: $X \twoheadrightarrow Y$ 且 $Y \twoheadrightarrow Z \Rightarrow X \twoheadrightarrow (Z - Y)$
				- 为什么减 Y: 只有 Z 中落在 Y 之外的部分才被 X 新多值决定(Z 与 Y 重叠的属性语义已被 $X \twoheadrightarrow Y$ 钉住, $Y \twoheadrightarrow Z$ 给不了新独立性). 按 Y 与 Z 关系分三种:
					- $Y \cap Z = \emptyset$(不相交): $Z - Y = Z$, 退化成干净传递 $X \twoheadrightarrow Z$(和 FD 传递一样)
					- $Y \subseteq Z$(Y 从属于 Z): 只剩 $X \twoheadrightarrow (Z - Y)$, Z 落在 Y 内那部分已由 $X \twoheadrightarrow Y$ 管, 不重复给
					- 相交但不从属: 扣掉公共的 $Z \cap Y$, 剩下 $Z - Y$ 才是新决定的
			- A7(FD+MVD) $X \rightarrow Y \Rightarrow X \twoheadrightarrow Y$(FD是MVD特例)
			- A8(FD+MVD, 合并/coalescence 律): 若 $X \twoheadrightarrow Y$, $Z \subseteq Y$, 且存在与 Y 不相交的 W($W \cap Y = \emptyset$)使 $W \rightarrow Z$, 则 $X \rightarrow Z$
				- 直觉: MVD 让 Z(⊆Y)对一个 X "见谁都配"(每个 Z 值都和每个 W 值同行过); FD $W \rightarrow Z$ 又要求"一个 W 只配一个 Z". 二者只有在"X 其实只有一个 Z 值"时才不冲突 —— 否则 X 若有 $z_1 \neq z_2$, 独立性逼着某个 w 同时和 $z_1, z_2$ 同行, 违反 $W \rightarrow Z$. 故塌缩为单值 $X \rightarrow Z$
		- 性质: 对称性, 传递性, FD 是 MVD 特例; 平凡 MVD(定义4.12): $U - XY = \emptyset$
		- MVD vs FD: FD 规定某些元组不能出现(相等产生依赖), MVD 要求某些元组必须出现(元组产生依赖); FD 有效性与属性集范围无关, MVD 有关
	- 嵌入型 MVD(eMVD, 定义4.13): $X \twoheadrightarrow Y$ 在 R(U) 上不成立, 但在某真子模式 W 上成立
- **4.3 关系模式分解**
	- 为什么分解: 拆大表为小表, 消除四大异常; 分解同时是属性集/FD集/当前关系值的分解
		- 例 SCT → SC(S#,C#,Grade)+CT(C#,Teacher)+TD(Teacher,Dept): 教师系别从存 N 次降到 1 次, 更新 O(N)→O(1)
	- 分解的两个要求: 无损连接 + 保持函数依赖
	- 泛关系假设: 假设所有属性可放进一张大表(泛关系), 再被分解; 即先有 r 再谈分解
	- 分解的定义(定义4.14): $\rho = \{R_1(U_1), \dots, R_k(U_k)\}$, $U = \bigcup U_i$, 且无 $U_i \subseteq U_j$
	- FD 集在子模式上的投影(定义4.15): $\pi_{U_i}(F) = \{X \rightarrow Y \in F^+ \mid XY \subseteq U_i\}$
	- 两个核心等价问题: 数据是否等价(用"无损分解") + 依赖是否等价(用"保持依赖")
		1. 无损联接分解(定义4.16)
			- 无损: 分解再自然连接能还原原关系, 不多不少, 即 $r = \pi_{R_1}(r) \bowtie \dots \bowtie \pi_{R_k}(r)$; 否则有损
			- 投影连接运算 $m_\rho(r)$(定义4.17) + 引理4.4: $r \subseteq m_\rho(r)$(只会变多), $\pi_{R_i}(m_\rho(r)) = r_i$, 幂等性
			- 推论: $m_\rho(r) \neq r$ 即有损; 有损时连接结果元组增多 = 信息丢失
			- 悬挂元组(dangling tuple): 有损分解连接后多出来的元组, 使子关系不存在泛关系
			- 无损判别方法1: chase 表格法(算法4.3)
				- 构表 k 行(每模式)×n 列(每属性): $A_j \in R_i$ 填 $a_j$, 否则 $b_{ij}$
				- chase: 对每个 FD $X \rightarrow Y$, X 上相等的行把 Y 上的值改一致(有 a 则取 a, 否则统一 b, 下标取小), 直到表不变
				- 判定: 出现一整行全 a 则无损, 否则有损
			- 无损判别方法2(两个关系模式)
				- 定理4.4: $\rho = \{R_1, R_2\}$ 无损 $\iff (R_1 \cap R_2) \rightarrow (R_1 - R_2)$ 或 $(R_1 \cap R_2) \rightarrow (R_2 - R_1)$(公共属性能决定某一边剩余)
				- 定理4.5: $X \rightarrow Y$ 成立且 $X \cap Y = \emptyset$, 则 $\rho = \{U - Y, XY\}$ 无损
		2. 保持函数依赖的分解(定义4.18)
			- 保持 FD: 各子模式 FD 投影的并能蕴含原 F, 即 $(\bigcup \pi_{R_i}(F))^+ = F^+$, 不丢任何 FD
			- 检验算法4.4: 即检 $G = \bigcup \pi_{U_i}(F)$ 是否覆盖 F; 对每个 $X \rightarrow Y$ 算 $X^+$(关于 G) 看是否含 Y. **基于求闭包算法 4.1**
				1. 对每个Ui中的属性集 X 用F算闭包, 再选出在 Ui 中的属性, 于是就得到了 X 的各个 FD, 继而就是F的投影
				2. 得到所有F的投影, 然后看各个F中的FD能否由所有投影的并集推出. 本质还是求左部的闭包
			- 反例: R(ABC), $F = \{A \rightarrow B, B \rightarrow C, C \rightarrow A\}$, 分解 {AB,AC} 丢了 $B \rightarrow C$ => 不保持
	- 模式等价: 数据等价(无损分解衡量) + 依赖等价(依赖集闭包相同, 保持依赖衡量); 违反任一都不是好分解
- **4.4 关系模式规范化**
	- 范式概念
		- 基于 FD: 1NF, 2NF, 3NF, BCNF; 基于 MVD: 4NF; 包含关系 $1NF \supset 2NF \supset 3NF \supset BCNF \supset 4NF \supset 5NF$
		- 规范化 = 使模式达到某范式的过程; 实际最常用 3NF 和 BCNF(2NF 一般不单提)
	- 键(Key)
		- 超键(Superkey): $K \rightarrow U$, 能决定全部属性
		- 候选键(Candidate key): 最小超键(任何真子集都不再是超键), 简称键
		- 主键(Primary key): 多个候选键中选定的一个
		- 主属性: 在某候选键中的属性; 非主属性: 不在任何候选键中的属性
		- 全键(All-key): 整个属性组才是候选键
	- 求全部候选键(F 先化最小覆盖)
		- 属性分四类: $C_1$ 不在任何 FD 出现; $C_2$ 仅在左部; $C_3$ 仅在右部; $C_4$ 左右都出现
		- 候选键必含 $C_1 \cup C_2$; 若 $(C_1 \cup C_2)^+ = U$ 或 $C_4 = \emptyset$ 则它是唯一候选键, 否则逐一/组合并入 $C_4$ 属性算闭包凑 U
	- 1NF(定义4.19): 每个属性值都是不可分的原子值; 是关系模式最起码的条件
	- 2NF(定义4.23): 1NF 且所有非主属性不是部分依赖于某个候选键, 即不能有某个非主属性只依赖候选键中的某个属性真子集. **但是可以是依赖于非主元素, 非超键**
		- 本质: 消除非主属性对键的**部分**函数依赖
	- 3NF(定义4.24): 非主属性对候选键既不部分依赖也不传递依赖
		- 本质: 在 2NF 上消除非主属性对键的**传递**依赖
		- 推论2: 每个 FD $X \rightarrow A$ 满足下列之一即 3NF —— $A \in X$(平凡) / X 是超键 / A 是主属性. 即消除同时违反3种情况的情况: 一个非超键决定了一个非主元素, 而且是非平凡的
		- 但是无法消除非主属性决定主属性
	- BCNF(定义4.25): 任何非平凡 FD $X \rightarrow Y$ 的左部 X 都含某候选键, 即为超键
		- 本质: 在 3NF 上消除**主属性**对键的部分和传递依赖
		- 3NF 但非 BCNF 经典例 R(S街道,C城市,Z邮编), $F = \{CS \rightarrow Z, Z \rightarrow C\}$: $Z \rightarrow C$ 左部非超键但 C 是主属性 => 属 3NF 不属 BCNF; 分解 R1(Z,C)+R2(S,Z) 无损但不保持 FD
	- 4NF(定义4.26): 每个非平凡 MVD $X \twoheadrightarrow Y$ 的 X 都是超键
		- 本质: 消除非平凡且非 FD 的多值依赖; $4NF \Rightarrow BCNF$, 反之不然
	- 判断最高范式: 求候选键 → 定主/非主属性 → 依次查 1NF(可分?)→2NF(非主部分依赖)→3NF(非主传递依赖)→BCNF(主属性对键部分/传递依赖)
	- 3NF 分解算法(算法4.4, **无损+保持FD**)
		- F 化最小覆盖 → 孤立属性单独成 $R_0$ → 按 FD 左部相同分组成各 $R_i$ → 再补一个候选键构成的 $R_{ck}$ 保证无损(若已含则省)
		- 结论: 任何模式都可分解为一组 3NF, 既无损又保持 FD
	- BCNF 分解算法(算法4.5, **保证无损, 可能不保持FD**)
		- 反复找不满足 BCNF 的 $R_i$(存在 $X \rightarrow A$ 且 X 不含候选键), 拆成 $\{XA\}$ 和 $\{U_i - A\}$, 直到全为 BCNF
		- 缺点: 涉及 $F^+$ 计算, 指数级; 判断是否 BCNF 是 NP 完全问题; 如 STJ→ST+TJ 不保持 FD
	- 规范化过程总结(每步消除什么)
		- 1NF --非主属性对键的部分依赖--> 2NF
		- 2NF --非主属性对键的传递依赖--> 3NF
		- 3NF --主属性对键的部分/传递依赖--> BCNF
		- BCNF --非平凡且非FD的多值依赖--> 4NF
	- 设计原则: 优先 BCNF, 若 BCNF 保不住 FD 则降为 3NF(保 FD + 无损); 好设计符合表达性, 分离性, 最小冗余性

## Chap 5. 数据库设计

- 基本术语
	- 数据库设计: 特定应用环境下, 按用户需求和支撑环境(DBMS/OS/硬件)构造最优数据库模式并建库及应用的过程
	- 概念模型: 对现实世界的抽象(抽取共同特性, 忽略细节), 独立于具体 DBMS, 常用 ER 模型
	- ER 三要素: 实体(矩形), 属性(椭圆), 联系(菱形)
	- 联系的元数: 一个联系涉及的实体集个数(一元/二元/三元)
	- 连通词(基数比约束): 实体间对应方式, 即 1:1 / 1:N / M:N
	- 基数参与度(参与约束, 记 (min,max)): E1 中每个实体与 E2 有联系实体数目的最小/最大值
- 5.1 数据库设计概述
	- 基本规律: 三分技术, 七分管理, 十二分基础数据
	- 结构(数据)设计 + 行为(处理)设计相结合
	- 设计方法: 面向数据(以信息需求为主) vs 面向过程(以处理需求为主); 因数据更稳定, 主用面向数据
	- 新奥尔良方法: 把设计分阶段(需求->概念->逻辑->物理); 规范设计法核心思想 = 过程迭代 + 逐步求精
	- 数据库的生命周期: 系统规划 - 数据库设计(需求分析 -> 概念结构设计 -> 逻辑结构设计 -> 物理结构设计) -> 系统实现 -> 运行维护
	- **6 个阶段**(重点):  需求分析 -> 概念结构设计 -> 逻辑结构设计 -> 物理结构设计 -> 数据库实施 -> 运行和维护
		- 需求分析: 最困难最耗时
		- 概念设计: 整个设计的关键
		- 独立于 DBMS: 需求分析 + 概念设计; 与 DBMS 密切相关: 逻辑设计 + 物理设计
	- 各阶段产出对应数据库各级模式: 概念设计->概念模式, 逻辑设计->逻辑模式+外模式, 物理设计->内模式
- 5.2 需求分析
	- 任务: 调查对象 -> 了解原系统 -> 明确需求 -> 确定新系统功能 -> 编写需求说明书
	- 重点: 用户的"数据"和"处理" — 信息要求 / 处理要求 / 安全性与完整性要求
	- 难点: 确定用户真实需求(用户缺计算机知识, 设计者缺业务知识), 解法是不断深入交流
	- 步骤: 收集 -> 分析整理(对数据做抽象) -> 编写需求说明书
	- 结果(产出): 系统范围图, 业务流程图, 数据流图(DFD), 数据字典
- 5.3 概念设计 (整个设计的关键)
	- 概念设计 = 把需求抽象成信息结构(概念模型)的过程, 与 DBMS 无关
	- E-R 模型
		- 双重性: 客观性(反映现实) + 主观性(选哪些属性取决于观察者目的)
		- 设计两大步: 先设计实体类型(不涉及联系), 再设计联系类型
	- 实体与属性的设计
		- 基本属性 vs 复合属性(可否再分); 单值 vs 多值属性(一个实体能否取多个值)
		- 多值属性处理: 用几个新单值属性表示, 或用一个新实体类型表示
		- 导出属性: 可由其他属性算出(如实发工资); 空值
	- 联系的设计
		- 一元(递归)联系: 1:1(名次) / 1:N(上下级) / M:N(零件组成)
		- 二元联系; 三元联系(M:N:P)
	- ER 模型操作: 实体/联系/属性的分裂(如垂直分裂)/合并/增删
	- 扩充 ER 模型 (EER)
		- 弱实体: 存在依赖于另一实体(如亲属依赖职工)
		- 普遍化/特殊化(ISA): "是...的一种"; 超类/子类有继承性 + 相同标识符, 子类可有额外属性
		- 聚集(Aggregation): "是...的一部分"
		- 范畴(Category): 子类的超类来自不同实体类型(如账户主 = 单位 U 个人)
	- 概念设计策略: 自顶向下 / 自底向上 / 由内向外(自底向上的特例) / 混合策略
	- 概念设计方法: 集中式模式设计法(适合小规模) vs 视图集成法
	- 局部视图设计: 确定范围 -> 实体定义 -> 联系定义 -> 属性分配
		- 定属性原则: 属性不可再分; 实体与属性是 1:N; 不同实体的属性间无直接关联
	- 视图集成
		- 全局 ER 不是各局部 ER 的简单拼凑
		- 步骤: 确定公共实体 -> 合并两两局部 -> 检查并消除冲突
		- **冲突类型**(重点): 命名冲突(同名异义/异名同义), 属性冲突(域/单位不同), 结构(类型)冲突(同一对象抽象成不同类型), 约束冲突
		- 消除冗余: 冗余数据(可由其他数据导出) + 冗余联系(可由其他联系导出)
		- 集成策略: 二元梯形 / n 元 / 二元平衡
- 5.4 逻辑设计 (考点: ER->关系转换)
	- 任务: 在概念设计基础上给出与 DBMS 相关的逻辑模式(如把 ER 图转成关系模型)
	- 步骤: 从 ER 导出初始模式 -> 关系规范化 -> 模式评价/修正 -> 用 DBMS 语法描述
	- **ER -> 关系模型 转换规则**
		- 实体 -> 关系模式: 属性即实体属性, 实体键即关系键
		- 非原子属性: 多值属性纵向展开, 复合属性横向展开
		- 1:1 联系: 独立成模式, 或并入任一端(被并入端加对方主键作外键)
		- 1:N 联系: 独立成模式, 或并入 N 端(N 端加 1 端主键作外键)
		- M:N 联系: 必须独立成模式, 键 = 两端主键的组合(两者同时也是外键)
		- 三元联系: 1:1:1 / 1:1:N 转 3~4 个模式; 1:M:N / M:N:P 转 4 个模式
		- 键完全相同的多个模式可合并; 自联系按 1:1/1:N/M:N 处理但命名要区分
	- 优化调整: 结构上用规范化减冗余(达 3NF/BCNF); 性能上减连接运算 + 水平/垂直分解避免过大关系
	- 用户子模式(外模式)设计: 适应不同用户需求, 提供逻辑独立性, 保证数据安全性
- 5.5 IDEF1X 方法简介
	- IDEF1X: 建立(关系)数据模型的经典方法; IDEF = ICAM DEFinition method
	- 实体: 独立实体(直角框) vs 非独立实体(圆角框)
	- 属性: 主键(横线上方) / 非主属性(横线下方); 外键标 (FK)
	- 联系基数: 多端用一个圆点表示
	- **标识 vs 非标识关系**(重点)
		- 标识关系: 父实体主键贡献给子实体作主键的一部分; 子实体存在依赖父实体; 实线 + 圆角框
		- 非标识关系: 父实体主键作子实体的非主键属性; 虚线; 分强制性/非强制性
		- M:N: 不确定关系, 主键不贡献作外键, 转关系模型时拆成两个 1:N
- 5.6 物理设计
	- 物理设计 = 为逻辑模型选最适合的物理结构(存储结构 + 存取方法), 依赖 DBMS/OS/硬件
	- 步骤: 确定存储结构 -> 存放位置 -> 存取方法 -> 系统配置 -> 评价
	- 存储结构: 权衡 存取时间 / 存储空间 / 维护代价(三者常矛盾, 取折中)
	- 存放位置: 表与索引分不同磁盘, 大表分片, 日志与数据分开 -> 提高 I/O 并行
	- **存取方法**(重点)
		- 索引法: 按属性建索引(如 B+树), 建在单个关系上
		- 聚簇(Cluster)法: 聚簇键相同的元组存连续物理块; 一个关系只能有一个聚簇; 利于 ORDER BY/GROUP BY/连接
		- HASH 法: 按关键字算存储地址; 适合等值/相等比较且关系大小可预知
		- 该建索引: 主键/外键, 常做连接或查询条件的属性, 聚集函数(MIN/MAX/SUM..)及 EXISTS 查询, 读为主的关系
		- 不该建索引: 不常用属性, 值少或分布不均的属性, 频繁变动或较小的关系
	- 系统配置: 调存储分配参数(用户数/缓冲区/锁数目等), 先用默认值再按环境调优
- 5.7 数据库实施
	- 实施工作: 用 DDL 定义结构 -> 组织数据入库 -> 编制调试应用程序 -> 试运行
	- 数据装载: 实施阶段最繁重的工作; 人工入库 = 筛选 -> 格式转换 -> 输入 -> 校验; 大型系统用输入子系统
	- 应用程序设计与数据库设计并行进行; 调试可先用模拟数据
	- 试运行(联合调试): 功能测试 + 性能测试
	- 运行与维护(DBA 负责)
		- 转储和恢复: 定期备份数据库和日志
		- 性能监督, 分析, 改进
		- 数据库重组: 不改逻辑/物理结构, 只重排存储位置/回收垃圾(物理存储变坏时)
		- 数据库重构: 应用环境变化时调整模式/内模式; 变化太大则生命周期结束, 需重新设计

## Chap 6. 数据库物理存储

- 基本术语
	- 记录(Record): 存储层讨论的数据单位, 对应逻辑层的元组
	- 块/页(Block/Page): 外存和缓冲区交换的基本单位, 一个块可存多条记录
	- 访问结构(Access Structure): 辅助定位记录的结构, 典型例子是索引
	- 文件组织(File Organization): 数据组织成记录, 块和访问结构的方式, 包括记录和块在磁盘上的存储方式及相互联系
	- 存取方法(Access Method): 对文件采取的存取操作方法; 一种文件组织可有多种存取方法
	- 索引: 主文件之外的辅助存储结构, 索引项 = (索引字段值, 行指针); 不改变主文件物理结构但提速
	- 主文件: 存放实际记录的数据文件, 即被索引定位的对象; 索引文件: 存索引项的辅助文件
- 6.1 物理存储与文件
	- 存储体系(速度递减/容量递增/价格递减): 高速缓存 > DRAM内存 > 非易失主存 > 闪存(SSD) > 磁盘
		- 易失: 高速缓存/DRAM; 非易失: 闪存/磁盘/非易失主存
		- CPU 与内存按"存储单元(字)"访问; 外存按"块"访问, 数据须先装入内存才能被 CPU 处理
	- 磁盘结构: 盘片/磁头/磁道/柱面/扇区; 读写单位 = 扇区(Sector); 块/簇 = 若干连续扇区
	- **磁盘读写时间 = 寻道时间 + 旋转时间 + 传输时间**(重点)
		- 顺序读写快(只有传输时延), 随机读写慢(寻道+旋转+传输); 优化目标: 降 I/O 次数 + 降寻道/旋转延迟
	- RAID(廉价冗余磁盘阵列): 并行读写提速 + 奇偶校验纠错提可靠; 含镜像/位交叉/块交叉校验等
	- 记录存储: 定长 vs 变长(分隔符/指针区分); 跨块 vs 不跨块(跨块靠指针连接, 省空间但需串行)
	- 磁盘块分配方式: 连续 / 链接 / 按簇 / 索引
	- **文件组织四种**(重点, 选填爱考特点对比)
		- 无序文件(堆文件 heap): 记录存任意空位; 更新快, 检索慢(要全扫)
		- 有序文件(顺序文件 sequential): 按排序字段(常为主码)有序存; 检索快, 更新慢(要移动记录或用溢出文件)
		- 散列文件(hash): 按散列函数算桶号存; 检索更新都较快; 不同记录可能撞同一桶(桶内顺序找)
		- 聚簇文件(clustering): 相同/相似属性值的记录存连续簇块; 多表聚簇提高连接查询速度
	- 数据库重组(Reorganization): 移走被删记录使有效记录连续存放, 回收空间(无序/有序文件都需周期性重组)
	- openGauss 物理存储: 表空间(Tablespace) > 数据库(Database) > 段(Segment) > 数据块(Block, 默认 8KB, 最小 IO 单位)
- 6.2 数据库索引
	- 索引一般特点: 是辅助结构(不改主文件物理结构); 索引文件比主文件小得多(可全装入内存); 一个表可建多个索引; 更新时索引与主文件须同步维护
	- 索引文件组织两种: 排序索引 / 散列索引
	- 几个 key 的区分(易混): 主码(唯一+最小) / 排序码(主文件据其排序) / 索引码(=索引字段, 不一定唯一) / 搜索码(查找用的属性)
	- SQL: 定义主键时系统自动建主索引; DBMS 自动维护所有索引; DROP TABLE 时其上索引自动撤销
	- **稠密 vs 稀疏索引**(重点)
		- 稠密(dense): 主文件每个索引字段值都有索引项
		- 稀疏(sparse): 只有部分值有索引项; **要求主文件按该字段排序**; 空间少/维护轻, 但慢
	- **主索引 vs 辅助索引**(高频考点)
		- 主索引: 建在有序主文件的排序码(通常主码)上; 每个存储块一个索引项(块锚 anchor); **是稀疏索引**; **一个主文件只能有一个**
		- 辅助索引: 建在非排序字段上; **是稠密索引**; **可以有多个**
	- **聚簇 vs 非聚簇索引**(高频考点)
		- 聚簇索引: 索引中邻近的记录在主文件中也邻近存储; **能决定记录存储位置**; **一个主文件只能一个**
		- 非聚簇索引: 主文件中不一定邻近; 只用于查询; **可以多个**
		- 主索引通常是聚簇索引; 辅助索引通常是非聚簇索引
	- 倒排索引: 词 -> 包含它的文档列表 (vs 正排: 文档 -> 它含的词); 全文检索用
	- 多级索引: 索引项太多时对索引再建索引, 层层向上(B+树就是一种)
	- **B+树索引**(只考概念)
		- 树型组织的多级索引, **自动平衡**(所有叶结点在同一层)
		- 非叶结点指针 -> 索引块; 叶结点指针 -> 主文件数据块/记录
		- **叶结点按顺序用指针链接**(支持范围查询); 叶结点集合即完整的最低级索引
		- 指向主文件的指针只在叶结点; 索引字段值在叶和非叶都可能出现; 指针利用率 50%~100%
		- 插入可能"分裂", 删除可能"合并", 可连锁反应直到根结点
		- **B树 vs B+树**: B树每个键值只出现一次(叶或非叶都可, 指向主文件指针随之); B+树键值在叶/非叶重复, 指向主文件指针只在叶结点, 且叶结点间有链接
	- **散列索引**
		- 静态散列: 桶数 M 固定; M 过大浪费, M 过小溢出桶多检索慢
		- 动态散列(桶数随键值增长): 可扩展散列 / 线性散列
		- 可扩展散列: 用指针数组(目录)做间接层, 取散列值前 i 位定位; 桶满则目录翻倍(长度总是 2 的幂)
		- 线性散列: 桶数按"平均装填比例"线性增长(每次 +1 桶); 取散列值低位; 允许溢出块

## Chap 7. 查询处理与查询优化

- 基本术语
	- 查询处理: 从用户查询语句到得到结果的整个过程
	- 查询优化: 从众多等价执行策略中找出高效的那个; 是 DBMS 关键技术
- 7.1 引言
	- **查询处理四步骤**: 查询转内部表示(语法树) -> 按等价规则变换成优化形式 -> 选底层操作算法 -> 生成查询计划(算代价选最小)
	- 实现方式: 解释(不留可执行代码) vs 编译(生成访问模块 AM 存盘, 一次编译多次执行)
	- 优化途径: 代数优化(独立于存取路径) / 物理优化(依赖存取路径) / 规则优化 / 代价估算优化 / 语义优化
	- 查询代价: 集中式 = I/O + CPU; 多用户再 +内存; 分布式再 +网络传输; 通常 I/O 是主要代价
	- 引例(优化的必要性): 选课查询, 先做选择/投影再连接, 中间结果大大减小(Q1 笛卡尔积极慢 -> Q3 先选择+用索引仅数秒)
- 7.3 代数优化
	- 基本原则: 尽量减小中间结果; **先做选择/投影(一元, 缩小关系), 后做连接/笛卡尔积(二元, 费时且结果大)**
	- 等价变换规则: 选择串接/交换, 投影串接, 选择与投影交换, 连接/笛卡尔积交换律与结合律, 选择对连接的分配律, 投影对连接的分配律
	- 优化策略: 选择尽早做; 投影选择同时做; 选择与其前的笛卡尔积合并成连接; 找公共子表达式
	- 优化算法(对语法树): 选择尽量下移到叶端 -> 投影下移 -> 选择投影串接合并 -> 内节点分组生成程序
- 7.4 物理优化
	- 物理优化 = 依赖存取路径, 选存取策略(顺序扫描 vs 索引 vs 散列)
	- 选择操作实现: 
		1. 顺序扫描(小关系/选中比例大/无索引)
		2. 利用各种存取路径: 索引(B+树), 散列
		- 启发式: 主键等值优先主索引; 非主键等值看比例(<15% 用无序索引, 否则聚簇索引或顺序扫描); 范围查询用索引顺序集; AND 用多属性索引; OR 尽量避免(要做并, 开销大)
	- **连接操作四方法**(重点): 嵌套循环法(nested loop) / 索引(散列)匹配法 / 排序归并法(sort-merge) / 散列连接法(hash join)
		- 嵌套循环: 选物理块少的关系作外关系
		- 启发式: 都已按连接属性排序 -> 排序归并; 一方有索引/散列 -> 它作内关系(索引/散列匹配法); 都很小 -> 嵌套循环; 否则 -> 散列连接
	- 投影操作: 垂直减小关系; 可与选择/连接同时做(不加额外 I/O); 结果需消除重复元组(排序/散列)
- 7.5 代价估算优化 (*选学)
	- 对各执行策略算代价选最小; 解释执行多用规则优化, 编译执行值得用代价估算
	- 代价 = I/O + CPU + 通信; I/O代价 ≈ I/O次数 × 单次代价(寻道+等待为主)
	- 统计参数: 元组数 / 块因子 / 不同值个数 / 选择因子 / 索引级数; 连接选择因子 js 估算连接结果大小

## Chap 8. 事务管理

- 基本术语
	- 事务(Transaction): 一组数据库操作组成的逻辑工作单元, 不可分割(all or nothing)
	- BEGIN TRANSACTION 开始; COMMIT(提交, 更新写回磁盘) / ROLLBACK(回滚, 撤销所有已做更新) 结束
	- 事务管理 = 恢复技术(故障时保 ACID) + 并发控制(并行时保 ACID)
- 8.2 事务 — ACID 特性(重点必背)
	- 原子性(Atomicity): 事务中操作要么都做要么都不做
	- 一致性(Consistency): 从一个一致状态变到另一个一致状态
	- 隔离性(Isolation): 并发事务互不干扰
	- 持续性(Durability): 一旦提交, 改变永久生效
	- 基本操作: read(X) / write(X)
	- 事务状态: 活动 -> 部分提交 -> 提交; 活动 -> 失败 -> 中止
	- SQL: COMMIT / ROLLBACK; `SET TRANSACTION` 设隔离级别(READ UNCOMMITTED / READ COMMITTED / REPEATABLE READ / SERIALIZABLE)
		- COMMIT表示提交，即提交事务的所有操作。具体地说就是将事务中所有对数据库的更新写回到磁盘上的物理数据库中去，事务正常结束。
		- ROLLBACK表示回滚，即在事务运行的过程中发生了某种故障，事务不能继续执行，系统将事务中对数据库的所有已完成的操作全部撤消，滚回到事务开始时的状态。这里的操作指对数据库的更新操作。
- 8.3 故障分类
	- 事务故障: 影响单个事务(逻辑错误/系统错误); 恢复 = UNDO 撤销该事务
	- 系统故障: 系统停转需重启(掉电/OS崩/CPU故障); 内存丢失但不破坏磁盘数据库; 导致不一致的原因有 (1) 未commit的已经写到数据库; 已提交的更新还在缓冲区; 恢复 = UNDO 未完成 + REDO 已提交
	- 介质故障: 外存损坏(磁盘坏); 破坏性最大但概率最小; 恢复 = 重装备份 + REDO
- 8.4 恢复技术
	- 基本原理: **冗余**(用存在别处的冗余数据重建)
	- 两种冗余手段: 数据备份(后备副本) + 日志文件, 通常一起用
	- 备份: 静态(脱机, 备份时停止访问) vs 动态(联机, 边备份边访问); 增量备份 vs 海量(全量)备份
	- 日志文件: 记录事务对数据库的更新; 内容 = 事务标识TID / 操作类型 / 对象 / 前像(旧值) / 后像(新值); 以记录为单位 或 以数据块为单位
	- **登记日志两原则**(重点): (1)严格按并发执行的时间次序登记; (2)**先写日志后写数据库(WAL, 先记后写)**
	- 恢复策略
		- 事务故障: 反向扫描日志, 对更新做逆操作(写回前像) = UNDO
		- 系统故障: 正向扫描日志, 已提交(有COMMIT)入 REDO 队列, 未完成(无COMMIT)入 UNDO 队列; 先 UNDO 再 REDO
		- 介质故障: 重装最新备份 + REDO 已提交事务; 需 DBA 介入
	- 检查点(checkpoint)技术: 减少恢复时要扫描的日志量; 检查点之前已提交的事务不必 REDO; 故障时 检查点后提交的 REDO, 未完成的 UNDO
- 8.5 并发控制
	- **并发引起的三类不一致**(重点)
		- 丢失修改(lost update): T2 的提交覆盖了 T1 的修改(订票例子)
		- 读脏数据(dirty read): T2 读了 T1 修改但随后 ROLLBACK 的数据
		- 不可重复读(non-repeatable read): T1 两次读同一数据结果不同(含幻读: 记录数变了)
	- 根因: 并发破坏了事务的隔离性
	- **可串行化(Serializable)**: 并发调度的结果 = 某个串行调度的结果, 是并发正确性的准则
	- 冲突操作: 属于不同事务 + 针对同一对象 + 至少一个是写(读写冲突/写写冲突)
	- 前趋图(precedence graph)判定: **有回路 -> 不可串行化; 无回路 -> 可拓扑排序得到等价串行调度**
- 8.6 基于锁的并发控制
	- 锁类型: 排他锁 X(写锁, 加锁后他人不能再加任何锁) / 共享锁 S(读锁, 他人只能再加 S) / U锁(更新锁, 读时先加 U, 写时升级为 X, 提高并发)
	- **三级封锁协议**(重点)
		- 1级: 修改前加 X 锁到事务结束 -> 防丢失修改
		- 2级: 1级 + 读前加 S 锁、读完即放 -> 再防读脏数据
		- 3级: 2级 + 读前加 S 锁、到事务结束才放 -> 再防不可重复读
	- **两段锁协议(2PL)**(重点): 扩展阶段(只申请锁不释放) + 收缩阶段(只释放不申请); **遵守 2PL => 可串行化**(充分条件); 但遵守 2PL 仍可能死锁
	- 活锁: 某事务一直被插队而无限等待; 解决 = 先来先服务
	- 死锁: 事务间循环等待
		- 预防: 一次封锁法(一次锁全部, 降并发) / 顺序封锁法(按规定顺序加锁) / wait-die(老等少) / wound-wait(老抢少)
		- 检测: 超时法 / 等待图法(有回路 = 死锁)
		- 解除: DBMS 干预, 撤销代价最小的事务
	- 多粒度封锁 + 意向锁: 显式封锁/隐式封锁; IS / IX / SIX(=S+IX); 加锁自上而下, 释放自下而上; 提高并发减少加锁开销
- 8.7 其他并发控制技术
	- 时间标记法: ts(T), tw(数据), tr(数据). 按事务时间戳定串行次序; 不用锁所以无死锁(但可能活锁)
		- 乐观并发控制: 执行时不检查, 提交时才验证可串行性; 三阶段 = 读阶段 / 验证阶段 / 写阶段. 3个条件满足一个就不存在访问冲突
- 8.8 openGauss 并发控制 — MVCC
	- MVCC(多版本并发控制): 写事务不原地改, 保留旧版本+新版本; 读事务按可见性选版本
	- 读-写不互相阻塞(读老版本写新版本); 写-写冲突仍阻塞(走 2PL)
	- 元组头记 xmin(插入事务号) / xmax(删除事务号)决定可见性窗口; 用快照判断可见性

## Chap 9. 数据库完整性和安全性

- 基本术语
	- 完整性: 数据的正确性, 有效性, 相容性(防"不对"的数据)
	- 安全性: 防止非法使用导致的数据泄露/篡改/破坏(防"坏人")
	- 区别记忆: 完整性面向"无意的错误", 安全性面向"恶意的非法访问"
- 9.1 引言
	- 数据出错四原因: 软硬件故障 / 并发引起不一致 / 更新操作有误 / 自然或人为破坏
	- DBMS 四项数据控制功能: 数据库恢复 / 并发控制 / 完整性 / 安全性
- 9.2 数据库完整性
	- 约束作用对象: 列 / 元组 / 关系 三种
	- 静态约束(某状态应满足, 最重要) vs 动态约束(状态变迁时新旧值应满足); 共 6 类(静态/动态 × 列/元组/关系)
	- **实体完整性 + 参照完整性 = 关系模型的两个不变性**(重点)
	- 完整性控制三功能: 定义 / 检查 / 违反时的处理
	- 检查时机: 立即执行约束(语句后立即查) vs 延迟执行约束(事务结束才查)
	- **参照完整性的几个问题**(重点)
		- 外键能否取空值
		- 删除被引用元组的策略: 级联删除(CASCADE) / 受限删除(RESTRICT) / 置空值(SET NULL)
		- 插入引用元组的策略: 受限插入 / 递归插入
		- 修改主键: 不允许 或 允许(须保唯一非空)
	- **完整性约束的说明方式**(重点)
		- CHECK 子句: 只约束定义它的那个关系
		- 断言(ASSERTION): `CREATE ASSERTION 名 CHECK 逻辑条件`; 表达更复杂约束, 但开销大
		- 存储过程: 编译好存库里供调用
		- 触发器(trigger): 更新时自动执行; 又称主动规则 / ECA(事件-条件-动作)规则
- 9.3 数据库安全性
	- 计算机安全三类: 技术安全 / 管理安全 / 政策法律(本课只讲技术安全)
	- 评测标准: TCSEC(桔皮书, 美国国防部) -> TDI(紫皮书, 扩展到数据库); CC for ITSEC = ISO/IEC 15408
	- **TCSEC/TDI 安全级别**(由低到高): D < C1 < C2 < B1 < B2 < B3 < A1(四组七级)
	- 安全模型(层层设防): 用户标识鉴别 -> 存取控制 -> 视图 -> 审计 -> 数据加密
	- 用户标识与鉴别: 最外层措施(用户名 + 口令)
	- **存取控制两种**(高频考点)
		- 自主存取控制(DAC): C2 级; 通过 SQL 的 `GRANT` / `REVOKE` 实现; 权限 = 数据对象 + 操作类型; `WITH GRANT OPTION` 可转授; 缺点: 可能"无意泄露"
		- 强制存取控制(MAC): B1 级; 更严格; 主体有"许可证级别(Clearance)", 客体有"密级(Classification)"
			- 读规则: 主体许可证级别 >= 客体密级 才能读(向下读)
			- 写规则: 主体许可证级别 = 客体密级 才能写(同级写); 核心是禁止高级别主体更新低密级数据, 防泄漏
		- 先做 DAC 检查, 通过后再做 MAC 检查
	- 视图机制: 把保密数据对无权用户隐藏, 间接实现存取谓词控制
	- 审计(Audit): 把所有操作记入审计日志(Audit Log); 是 C2 以上级别必备; 费时空间故可选
	- 数据加密: 替换法 + 置换法(结合更安全); 标准 DES; 明文 -> 密文
- 9.4 数据库隐私性 (了解)
	- 统计数据库: 只能做聚集查询(count/sum/mean), 不能查单条记录; 但本质上仍无法保证隐私
	- 差分隐私: 相邻数据集(只差一条记录)的输出极接近, 攻击者难区分; ε 是隐私预算(越小保护越强); 靠加噪声实现
	- 中心化(面向结果发布) vs 本地化差分隐私(面向数据收集全流程, 如随机化应答 Randomized Response); 苹果/谷歌都在用
